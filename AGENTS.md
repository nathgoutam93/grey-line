# Repository Guidelines

## Roadmap
- GreyLine is becoming a real-time PvP close-quarters tactical shooter: teams, attack/defend rounds, destructible walls and doors, and sound as information. There is no planning phase and there are no AI opponents.
- The step-by-step build plan is in `docs/plan/`. Read `docs/plan/README.md` first (architecture, rules for implementing agents, definition of done), then only the step you are working on. Do the steps in order and follow each step's tasks, tests and commit plan rather than re-designing.

## Project Structure & Module Organization
- `project.godot` is the Godot 4.7 project entry; main scene is wired from there.
- `scenes/` contains playable scenes and feature flows (`main_menu`, `lobby`, `player`, `maps`, `ui`, `weapon`, `utilities`).
- `components/` holds reusable gameplay/UI components (health, movement, camera shake, weapon manager, fog of war, etc.).
- `scripts/` contains global/shared logic, including networking (`scripts/network/*`), profile data, and utilities.
- `resources/` stores typed data resources (`*.gd` resource classes, `*.tres` weapon/equipment/sound configs).
- `assets/`, `materials/`, and `shaders/` contain art/audio/render assets. `addons/` contains editor/runtime plugins.

## Build, Test, and Development Commands
- `godot4 --path . --editor`: Open the project in the Godot editor.
- `godot4 --path .`: Run the game using `run/main_scene`.
- `godot4 --headless --path . --export-release "Linux" dist/GreyLine.x86_64`: Build Linux export (preset in `export_presets.cfg`).
- `godot4 --headless --path . --export-release "Windows Desktop" dist/GreyLine.zip`: Build Windows export.

## Coding Style & Naming Conventions
- Follow existing GDScript style in this repo: typed variables where practical, `snake_case` for funcs/vars, `PascalCase` for `class_name` types.
- Keep scene and resource file names lowercase with underscores (for example `player_hud.tscn`, `weapon_sounds.gd`).
- Indentation is mixed historically (tabs and spaces); match the surrounding file instead of reformatting unrelated code.
- Keep `.gd.uid` files tracked with their corresponding scripts/scenes.

## Testing Guidelines
- Run the headless suite before opening a PR: `tests/run_tests.sh` (all suites, about four minutes) or `tests/run_tests.sh unit sync` for a subset. It finds Godot via `$GODOT`, `godot4`/`godot` on PATH, or the macOS app, and exits non-zero on any failure (logs path is printed).
- Pre-commit hook (no CI; tests run locally): enable once per clone with `git config core.hooksPath .githooks`. `.githooks/pre-commit` runs the suite on the *staged* snapshot (mirrored into `.git/precommit-tree`) whenever game files (`.gd`, `.tscn`, `.tres`, `.gdshader`, `.cfg`, `project.godot`) are staged, and aborts the commit on failure. `GREYLINE_PRECOMMIT_SUITES="unit sync"` runs a subset; `SKIP_TESTS=1 git commit ...` or `--no-verify` skips it.
- Suites: `unit` (`tests/unit/unit_tests.gd`: input frames, team rules/spawns/visuals and FFA fallback, bot brain frames, history, interpolation, reconciliation, one-tick movement, ammo sync, server vision/hearing, wall hits/blast cover/fog mirrors, doors and pickup interaction, round phases/roles/objective/reset/spectating, input life validation, ASCII generation and round-map validation) and two-process host+client scenarios in `tests/net/`: `sync` (input clock, prediction, snapshots), `visibility` (fog of war + attenuated audio presence and silent slow-walk), `firing` (owner prediction, ammo/slot reconciliation), `match` (kills, respawn, team score limit and results), `bots` (puppet replication, movement, scoring, respawn and removal), `teams` (lobby assignment/switch validation, teammate visibility, enemy vision, friendly fire and team scoring), `destruction` (cell/fog replication, breach sight, full-state repair, authority and reset), `doors` (quiet interaction, bot kicks, audible hidden source, full-state repair, authority and reset), `rounds` (host map selection, freeze, elimination/no respawn, fresh-life/destruction reset, timeout, capture, timer/role sync, spectating and match results), `cqc` (generated-map loading, material/breach and fog replication, doors, spectating a moving puppet, measured running time, capture and reset).
- Tests pass `--ephemeral-profile` (profile stays in memory, never saved) and use ports 3300+, so they don't touch your profile or a running game. `tests/` is excluded from exports.
- New network scenario: add `tests/net/<name>_test.gd` extending `net_test_base.gd` (override `run_host`/`run_client`; the client reports with `send()`, the host checks with `check()`), then add `<name>` to `ALL_SUITES` in `tests/run_tests.sh`. Pass `--map=<scene path>` to select a map before the host starts; the runner selects `map_1_rounds.tscn` for `rounds` and `cqc_1.tscn` for `cqc`.
- Host-side network tests can `await add_bot()` during a match, then script its `BotBrain` with `bot(id)`. Bots use negative ids and the normal server input pipeline; `MultiplayerSession.add_bot()` / `remove_bot(id)` also work in the lobby. Debug hosts have Add bot / Remove bot buttons beside Start.
- Network scenarios can override `run_host_lobby()` for checks before the match starts and use `find_wall_setup()` for visibility arrangements. `MultiplayerSession.set_team(id, team)` is server-only and can arrange test teams mid-match; client requests are restricted to balanced lobby switches. Maps can provide `SpawnPoints/AttackerSpawns` (Alpha) and `DefenderSpawns` (Bravo), with flat spawn points as fallback. Set the game mode's `teams_enabled` to false for FFA, or `friendly_fire` to true to permit teammate weapon damage. Frag explosions always damage both teams and the thrower within their radius, regardless of that setting.
- The lobby renders separate Alpha/Bravo rosters through `LobbyView`; five players balance 3–2, and roster rows are not capped at five. The `teams` suite verifies the five-player split on host and client. For a graphical fixture screenshot, run the unit scene without `--headless` and pass `-- --ephemeral-profile --lobby-preview=/tmp/greyline-lobby.png`.
- Slow-walk silences footsteps on the server, owner and proxies, including movement from knockback; equipment noise stays audible. World snapshot flags are bits: `FLAG_VISIBLE = 1`, `FLAG_FOOTSTEPS = 2`, and `FLAG_SPOTTED = 4` is reserved. Touch players toggle Walk under HUD Controls; its position is saved in the touch-layout settings.
- The host applies its own filtered world packet to local player presentation, including with no remote peers and while spectating; hidden authoritative players still simulate and take damage. The host also plays other players' footsteps only when its own packet carries `FLAG_FOOTSTEPS`, like a client. Character body polygons must inherit the root fog material through the intermediate `polygons` node; allies bypass that material. The `host_visibility` network suite covers host culling, breaches, allied/client visibility and spectating; graphical runs also compare rendered body pixels inside/outside the exact fog cone. See `docs/testing/host-visibility.md`.
- Destructible walls use 16 px TileMapLayer cells and a collision-free fog mirror under `FowMaskView/Level`. Regenerate the committed tileset with `godot4 --headless --path . -s tools/build_destructible_tileset.gd -- --ephemeral-profile`. The map-root `DestructionService` owns cell HP and reliable channel 3 updates; wall paths are relative to its parent. Clients request full state at map readiness and local player setup; `reset_all()` restores cells and clears partial damage on the server and peers. Existing static exterior walls stay indestructible.
- Weapons stop at the first wall cell: bullets deal `wall_damage` (default 10), knives `melee_wall_damage` (20); both fields survive pickup serialization. Frags deal 200 maximum wall damage with distance falloff. Wall damage resolves before player blast line-of-sight checks; intact environment cover blocks blast damage and knockback, while exposed teammates and the thrower still take damage.
- `Door` is a 64×8 Environment body with a viewport fog occluder. Interact toggles CLOSED/OPEN and reports 250 px noise for 0.4 s; depleting 60 HP (including one 60-damage knife kick) makes it permanently BROKEN and reports 900 px for 1 s. Door state uses reliable channel 3 and joins full-state/reset sync. Interactions dispatch through typed `Interactable` owners on the server and require that player's nearby interaction list; weapon pickups retain their existing replicated pickup flow.
- Hearing multiplies the source radius by up to four Environment ray hits: SOFT 0.6, REINFORCED 0.4, HARD/static cover 0.35, and closed doors 0.7. Open/broken doors and destroyed cells no longer attenuate. The visibility suite checks both distant footsteps suppressed by cover and nearby footsteps still audible through it.
- Destruction/door network fixtures live in `tests/fixtures/` and are instanced under `Map` with matching names on both peers. Run a network scenario without `--headless` and pass `--capture-dir=/tmp/greyline-step4` to save rendered client frames at its checkpoints. The shipped map retains its static exterior; these fixtures exercise Step 4 before the CQC map in Step 6.
- Game modes inherit `MatchGameMode` for typed shared team/friendly-fire rules and join the `game_mode` group. Runtime and network-test lookup uses that group rather than the deathmatch scene node name.
- Only the server despawns dead players; clients follow `MultiplayerSpawner` removal. Owner input uses the persistent `WorldSnapshots.submit_player_input` RPC on channel 0, then the owning player's normal `PlayerNetSync` queue. Setup sends a server-issued life ID; missing/dead players and mismatched lives reject in-flight input across round resets. Spectator targets are never input recipients.
- `PlayerController.actions_locked` cancels active equipment use and gates both authoritative and predicted fire/reload/switch/drop/interact actions. `movement_locked` also blocks movement/knockback while preserving aim; rounds allow walking during ROUND_END while actions and player damage stay locked. Phase changes set the action lock on server and clients together.
- `RoundGameMode` keeps fixed Alpha/Bravo teams and assigns attack/defend roles per half. WAITING requires a connected roster on both teams; FREEZE starts fresh role-based lives and resets destruction. LIVE ends on elimination, accumulated uncontested objective hold, or defender timeout. Elimination resolves at the end of the frame, so every death from one blast counts; mutual elimination is a defender win. Deaths in FREEZE do not respawn. Round score comes from wins, while `MatchScoreboard.round_scoring` preserves kill/death stats without adding kill points. Phases replicate end ticks; changing objective progress replicates at 5 Hz. Roles swap after `rounds_to_win - 1` finished rounds; the first team to the win limit ends the match.
- Dead round players spectate living teammates and use the existing pickup action (F) to cycle. The server validates spectate requests and builds snapshots from the selected teammate's position, facing and visibility-grace history. Camera, audio listener and fog follow that target; no remaining teammate means no fog vision. New round lives restore their own view.
- Lobby hosts cycle `MultiplayerSession.MAPS` with Change map; selection replicates reliably and clients cannot change it. Keep `MAPS` and the lobby `LevelSpawner` spawnable-scene list in sync when adding maps. `map_1_rounds.tscn` is the legacy dev attack/defend variant; Step 6 expands it to five clear spawns per role. `cqc_1.tscn` is the generated CQC map, with five spawns per role, three exterior doors, two breach sections, six rooms and one interior objective. Its round HUD shows score, role, phase/countdown, fractional objective progress and a spectator-next button. Round test coverage, graphical capture commands and remaining separate-machine playtests are recorded in `docs/testing/rounds.md`.
- Generated round maps use `scenes/maps/_template/round_map_template.tscn` and `tools/build_map.gd`; edit the ASCII `layout.txt`, then regenerate with `godot4 --headless --path . -s tools/build_map.gd -- --ephemeral-profile --layout=res://scenes/maps/cqc_1/layout.txt --out=res://scenes/maps/cqc_1/cqc_1.tscn --preview=res://scenes/maps/cqc_1/preview.png`. Never hand-edit generated scenes. `RoundMapBuilder` is shared by the CLI and validation; generator-owned resource/node IDs are normalized for deterministic output. Props derive runtime fog occluders from their collision shapes.
- Round-map validation checks every selectable round map for five clear spawns per role (24 px radius), attacker distance of at least 1400 px, exactly one objective and known wall materials. Generated maps are compared with their ASCII source, including cells, objective, doors, props and spawns. CQC route and open-door sight-line checks use real scene metrics; players run at 250 px/s in `player.tscn`. The `cqc` network fixture replays a test route through normal puppet input; it adds no gameplay AI. See `docs/testing/cqc-map.md` for measured timings, rendered loopback checks and the remaining human playtest.
- Still do a focused manual playtest for gameplay/feel changes: main menu -> host/join lobby -> start match -> verify replication, combat, and UI sync, with at least two clients (host + one client) on separate machines for networking changes.

## Commit & Pull Request Guidelines
- Recent commits are short, imperative summaries; optional prefixes like `fix:` are common. Keep subject lines specific.
- One logical change per commit (avoid mixing gameplay, UI, and asset churn).
- PRs should include: what changed, why, manual test steps/results, and screenshots/videos for visible UI/FX updates.
- Link related issue/task IDs when available.
