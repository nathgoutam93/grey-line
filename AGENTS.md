# Repository Guidelines

## Roadmap
- GreyLine is becoming a real-time PvP close-quarters tactical shooter: teams, attack/defend rounds, breakable doors and props (walls are indestructible), and sound as information. There is no planning phase and there are no AI opponents.
- The step-by-step build plan is in `docs/plan/`. Read `docs/plan/README.md` first (architecture, rules for implementing agents, definition of done), then only the step you are working on. Do the steps in order and follow each step's tasks, tests and commit plan rather than re-designing.

## Project Structure & Module Organization
- `project.godot` is the Godot 4.7 project entry; main scene is wired from there.
- `scenes/` contains playable scenes and feature flows (`main_menu`, `lobby`, `player`, `maps`, `ui`, `weapon`, `utilities`).
- `components/` holds reusable gameplay/UI components (health, movement, camera shake, weapon manager, fog of war, etc.).
- `scripts/` contains global/shared logic, including networking (`scripts/network/*`), profile data, and utilities.
- `resources/` stores typed data resources (`*.gd` resource classes, `*.tres` weapon/equipment/sound configs).
- `assets/`, `materials/`, and `shaders/` contain art/audio/render assets. `addons/` contains editor/runtime plugins.

## Build, Test, and Development Commands
- `godot4 --path . --editor`: Open the project in the Godot editor.
- `godot4 --path .`: Run the game using `run/main_scene`.
- `godot4 --headless --path . --export-release "Linux" dist/GreyLine.x86_64`: Build Linux export (preset in `export_presets.cfg`).
- `godot4 --headless --path . --export-release "Windows Desktop" dist/GreyLine.zip`: Build Windows export.

## Coding Style & Naming Conventions
- Follow existing GDScript style in this repo: typed variables where practical, `snake_case` for funcs/vars, `PascalCase` for `class_name` types.
- Keep scene and resource file names lowercase with underscores (for example `player_hud.tscn`, `weapon_sounds.gd`).
- Indentation is mixed historically (tabs and spaces); match the surrounding file instead of reformatting unrelated code.
- Keep `.gd.uid` files tracked with their corresponding scripts/scenes.

## Testing Guidelines
- Run the headless suite before opening a PR: `tests/run_tests.sh` (all suites, about four minutes) or `tests/run_tests.sh unit sync` for a subset. It finds Godot via `$GODOT`, `godot4`/`godot` on PATH, or the macOS app, and exits non-zero on any failure (logs path is printed).
- Pre-commit hook (no CI; tests run locally): enable once per clone with `git config core.hooksPath .githooks`. `.githooks/pre-commit` runs the suite on the *staged* snapshot (mirrored into `.git/precommit-tree`) whenever game files (`.gd`, `.tscn`, `.tres`, `.gdshader`, `.cfg`, `project.godot`) are staged, and aborts the commit on failure. `GREYLINE_PRECOMMIT_SUITES="unit sync"` runs a subset; `SKIP_TESTS=1 git commit ...` or `--no-verify` skips it.
- Suites: `unit` (`tests/unit/unit_tests.gd`: input frames, team rules/spawns/visuals and FFA fallback, bot brain frames, history, interpolation, reconciliation, one-tick movement, ammo sync, server vision/hearing, indestructible walls/blast cover/fog mirrors, breakable crates, doors and pickup interaction, round phases/roles/objective/reset/spectating, input life validation, reconnect slot hold/rekey/forfeit and frozen dropped bodies, ASCII generation and round-map validation) and two-process host+client scenarios in `tests/net/`: `sync` (input clock, prediction, snapshots), `visibility` (fog of war + attenuated audio presence and silent slow-walk), `firing` (owner prediction, ammo/slot reconciliation), `match` (kills, respawn, team score limit and results), `bots` (puppet replication, movement, scoring, respawn and removal), `teams` (lobby assignment/switch validation, teammate visibility, enemy vision, friendly fire and team scoring), `destruction` (crate break/collision/fog replication, sight through broken cover, full-state repair, authority and reset), `doors` (quiet interaction, bot kicks, audible hidden source, full-state repair, authority and reset), `rounds` (host map selection, freeze, elimination/no respawn, fresh-life/crate reset, timeout, capture, timer/role sync, spectating and match results), `cqc` (generated-map loading, indestructible walls, crate break and fog replication, doors, spectating a moving puppet, measured running time, capture and reset), `reconnect` (rounds: drop mid-round, frozen killable body, automatic rejoin under a new peer id with name/team/stats/round state, spectating until the next round, input in the next round, confirmed Leave forfeits) and `reconnect_dm` (deathmatch: body removed on drop, respawn with the held slot on rejoin).
- Tests pass `--ephemeral-profile` (profile stays in memory, never saved) and use ports 3300+, so they don't touch your profile or a running game. `tests/` is excluded from exports.
- New network scenario: add `tests/net/<name>_test.gd` extending `net_test_base.gd` (override `run_host`/`run_client`; the client reports with `send()`, the host checks with `check()`), then add `<name>` to `ALL_SUITES` in `tests/run_tests.sh`. Pass `--map=<scene path>` to select a map before the host starts; the runner selects `map_1_rounds.tscn` for `rounds` and `cqc_1.tscn` for `cqc`.
- Host-side network tests can `await add_bot()` during a match, then script its `BotBrain` with `bot(id)`. Bots use negative ids and the normal server input pipeline; `MultiplayerSession.add_bot()` / `remove_bot(id)` also work in the lobby. Debug hosts have Add bot / Remove bot buttons beside Start.
- Network scenarios can override `run_host_lobby()` for checks before the match starts and use `find_wall_setup()` for visibility arrangements. `MultiplayerSession.set_team(id, team)` is server-only and can arrange test teams mid-match; client requests are restricted to balanced lobby switches. Maps can provide `SpawnPoints/AttackerSpawns` (Alpha) and `DefenderSpawns` (Bravo), with flat spawn points as fallback. Set the game mode's `teams_enabled` to false for FFA, or `friendly_fire` to true to permit teammate weapon damage. Frag explosions always damage both teams and the thrower within their radius, regardless of that setting.
- The lobby renders separate Alpha/Bravo rosters through `LobbyView`; five players balance 3–2, and roster rows are not capped at five. The `teams` suite verifies the five-player split on host and client. For a graphical fixture screenshot, run the unit scene without `--headless` and pass `-- --ephemeral-profile --lobby-preview=/tmp/greyline-lobby.png`.
- Slow-walk silences footsteps on the server, owner and proxies, including movement from knockback; equipment noise stays audible. World snapshot flags are bits: `FLAG_VISIBLE = 1`, `FLAG_FOOTSTEPS = 2`, and `FLAG_SPOTTED = 4` is reserved. Touch players toggle Walk under HUD Controls; its position is saved in the touch-layout settings.
- The host applies its own filtered world packet to local player presentation, including with no remote peers and while spectating; hidden authoritative players still simulate and take damage. The host also plays other players' footsteps only when its own packet carries `FLAG_FOOTSTEPS`, like a client. Character body polygons must inherit the root fog material through the intermediate `polygons` node; allies bypass that material. The `host_visibility` network suite covers host culling, cover breaking, allied/client visibility and spectating; graphical runs also compare rendered body pixels inside/outside the exact fog cone. See `docs/testing/host-visibility.md`.
- Walls are indestructible. They use 16 px TileMapLayer cells (`DestructibleWalls`, kept for the grid, per-cell materials and the collision-free fog mirror under `FowMaskView/Level`), but `DestructionMaterial.can_damage` rejects every material and kind; materials only set sound attenuation. Regenerate the committed tileset with `godot4 --headless --path . -s tools/build_destructible_tileset.gd -- --ephemeral-profile`. The map-root `DestructionService` owns reliable channel 3 state for wall cells, doors and `BreakableProp`s; paths are relative to its parent. Clients request full state at map readiness and local player setup; `reset_all()` restores cells, doors and props on the server and peers.
- Weapons stop at the first Environment hit. Breakable props (`scenes/props/crates/breakable_prop.gd`, on `crate.tscn` and so `sci_fi_crate.tscn`; 80 HP) take bullet `wall_damage` (default 10) and knife `melee_wall_damage` (20); both fields survive pickup serialization. Frags deal up to 200 structure damage to doors and props they have a clear line to, with distance falloff, resolved before player blast line-of-sight checks; intact cover blocks blast damage and knockback, while exposed teammates and the thrower still take damage. A broken prop loses collision, sprite and the fog occluders inside its collision box (including map_1's baked ones), plays its `break_sound` at the prop on every peer (world audio, not player noise), and is restored by `reset_all()`. Cars, trucks and containers are indestructible.
- `Door` is a 64×8 Environment body with a viewport fog occluder. Interact toggles CLOSED/OPEN and reports 250 px noise for 0.4 s; depleting 60 HP (including one 60-damage knife kick) makes it permanently BROKEN and reports 900 px for 1 s. Door state uses reliable channel 3 and joins full-state/reset sync. Interactions dispatch through typed `Interactable` owners on the server and require that player's nearby interaction list; weapon pickups retain their existing replicated pickup flow.
- Hearing multiplies the source radius by up to four Environment ray hits: SOFT 0.6, REINFORCED 0.4, HARD/static cover 0.35, and closed doors 0.7. Open/broken doors and destroyed cells no longer attenuate. The visibility suite checks both distant footsteps suppressed by cover and nearby footsteps still audible through it.
- Destruction/door network fixtures live in `tests/fixtures/` and are instanced under `Map` with matching names on both peers. Run a network scenario without `--headless` and pass `--capture-dir=/tmp/greyline-step4` to save rendered client frames at its checkpoints. The shipped map retains its static exterior; `test_crate.tscn` (a crate with a derived fog occluder) and `test_door.tscn` exercise destruction before the CQC map.
- Game modes inherit `MatchGameMode` for typed shared team/friendly-fire rules and join the `game_mode` group. Runtime and network-test lookup uses that group rather than the deathmatch scene node name.
- Reconnect: on registration the server issues each client a random 32-hex rejoin token (`_receive_rejoin_token`); the client keeps it with the host address/port and saves it to `user://rejoin_ticket.json` once the match starts (memory only with `--ephemeral-profile`). A client that drops out of a running match without confirming Leave keeps its slot until the match ends: the server keeps its name/team/avatar/stats (`MultiplayerSession.dropped_ids`) and emits `player_dropped`. Mid-match connections are admitted only through `_request_rejoin(token)` within 10 s; the server then rekeys the slot to the new peer id (`player_rejoined(old_id, new_id)`, `current_id(old)` resolves aliases, `holds_slot(id)` covers connected, dropped and rejoined slots). Game modes listen to `player_dropped`/`player_left`/`player_rejoined`, never `multiplayer.peer_disconnected`. In rounds the dropped body stays frozen (`PlayerNetSync.owner_dropped`: idle input, aim kept), killable and counted as alive for that round; its deaths count for the rejoined slot; a mid-round rejoiner spectates and plays from the next round. In deathmatch the dropped body is removed and the rejoiner respawns at once. The client auto-reconnects for 60 s after `server_disconnected` (fresh lobby scene first, because the map replicates on connect), then the main menu offers Rejoin match; `_match_closed_event` and `mark_match_over()` (match end) clear the ticket. Leave buttons open `LeaveMatchDialog`; confirming calls `MultiplayerSession.leave_match()`, which forfeits (`forfeit_match`) and releases the slot. The host leaving still ends the match (no host migration).
- Only the server despawns dead players; clients follow `MultiplayerSpawner` removal. Owner input uses the persistent `WorldSnapshots.submit_player_input` RPC on channel 0, then the owning player's normal `PlayerNetSync` queue. Setup sends a server-issued life ID; missing/dead players and mismatched lives reject in-flight input across round resets. Spectator targets are never input recipients.
- `PlayerController.actions_locked` cancels active equipment use and gates both authoritative and predicted fire/reload/switch/drop/interact actions. `movement_locked` also blocks movement/knockback while preserving aim; rounds allow walking during ROUND_END while actions and player damage stay locked. Phase changes set the action lock on server and clients together.
- `RoundGameMode` keeps fixed Alpha/Bravo teams and assigns attack/defend roles per half. WAITING requires a connected roster on both teams; FREEZE starts fresh role-based lives and resets destruction. LIVE ends on elimination, accumulated uncontested objective hold, or defender timeout. Elimination resolves at the end of the frame, so every death from one blast counts; mutual elimination is a defender win. Deaths in FREEZE do not respawn. Round score comes from wins, while `MatchScoreboard.round_scoring` preserves kill/death stats without adding kill points. Phases replicate end ticks; changing objective progress replicates at 5 Hz. Roles swap after `rounds_to_win - 1` finished rounds; the first team to the win limit ends the match.
- Dead round players spectate living teammates and use the existing pickup action (F) to cycle. The server validates spectate requests and builds snapshots from the selected teammate's position, facing and visibility-grace history. Camera, audio listener and fog follow that target; no remaining teammate means no fog vision. New round lives restore their own view.
- Lobby hosts cycle `MultiplayerSession.MAPS` with Change map; selection replicates reliably and clients cannot change it. Keep `MAPS` and the lobby `LevelSpawner` spawnable-scene list in sync when adding maps. `map_1_rounds.tscn` is the legacy dev attack/defend variant; Step 6 expands it to five clear spawns per role. `cqc_1.tscn` is the generated indoor CQC map: attackers start on a west street and breach a 150×106-cell house: a dog-legged central hallway (west half rows 58–64, east half rows 73–79, joined at x 109–115) with 25 smaller rooms off it and an east wing holding the objective room (36 doors, four exterior doors on the north and south faces). Defenders spawn in the east rooms around the objective, and the house is furnished with 39 pieces. Its round HUD shows score, role, phase/countdown, fractional objective progress and a spectator-next button. Round test coverage, graphical capture commands and remaining separate-machine playtests are recorded in `docs/testing/rounds.md`.
- Generated round maps use `scenes/maps/_template/round_map_template.tscn` and `tools/build_map.gd`; edit the ASCII `layout.txt`, then regenerate with `godot4 --headless --path . -s tools/build_map.gd -- --ephemeral-profile --layout=res://scenes/maps/cqc_1/layout.txt --out=res://scenes/maps/cqc_1/cqc_1.tscn --preview=res://scenes/maps/cqc_1/preview.png`. Never hand-edit generated scenes. `RoundMapBuilder` is shared by the CLI and validation; generator-owned resource/node IDs are normalized for deterministic output. Props derive runtime fog occluders from their collision shapes.
- Fake top-down 3D (`components/perspective/`, `shaders/perspective.gdshader`): every lifted visual is a mesh whose vertices carry their floor position plus `CUSTOM0` = (height px, outward normal xy, textured flag), built with `HeightMeshBuilder` (sides first, then roofs/layers low to high). The shader leans each point away from the camera centre by `h / (H - h)` (globals `perspective_camera`/`perspective_eye_height` in `project.godot [shader_globals]`, eye height 700) and collapses side faces turned away from the camera. All visuals share `Perspective.material()`; `Perspective.sync_camera()` sets the camera once per frame. Walls: `PerspectiveWalls` in the round-map template (merged runs of `DestructibleWalls`, height 40). Props: a `PerspectiveSprite` child of the prop's `Sprite2D` with a `PerspectiveProfile` (`resources/perspective/*.tres`): BOX (rect extruded, sprite as roof: crates, containers, doors), STACK (sprite silhouette repeated up to the height: cars, trucks) or SLICES (a strip of cross-section art). The sprite only stops drawing itself (`self_modulate`), so door rotation, broken-crate hiding and tints carry over. Visual only: collision, sight, hearing and the fog mirror stay flat; lifted visuals draw above players (z 20 + height/8) and are skipped headless. `tools/capture_perspective.tscn` renders flat/perspective comparisons (run with a window, `-- --ephemeral-profile --out=<dir>`).
- House furniture (`scenes/props/furniture/`: sofa, coffee table, TV stand, dining set, kitchen counter) blocks movement only: StaticBody2D on physics layer 2 (players collide with layers 1-2), so bullets, sight, hearing, throwables and fog ignore it, and the map builder adds no `FogOccluder` to props off layer 1. Layout letters: `h` sofa, `x` coffee table, `n` TV stand, `g` dining set, `k` kitchen counter (cover stays `c`/`v`/`t`); base orientation is sofa back north, TV and counter backs south. `RoundMapBuilder.PROP_VARIANTS` adds rotated letters (`H`/`j`/`J` sofa 180°/90°/270°, `X` coffee table 90°, `N`/`m`/`M` TV stand, `G` dining set 90°, `K`/`q`/`Q` counter); the builder rotates the prop and swaps its footprint for quarter turns. Baked lighting rotates with the art. Art comes from `tools/blender/furniture.py` (run Blender with `--background --factory-startup --python tools/blender/furniture.py -- [names]` from the repo root): 128 px/m top-down renders (`top.png`) and 10-slice strips (`slices.png`) under `assets/props/furniture/<name>/`, used at 0.5 scale with SLICES profiles at 24 height px per metre. Stairs wait for multi-level maps.
- Round-map validation checks every selectable round map for five clear spawns per role (24 px radius), attacker distance of at least 1400 px, exactly one objective and known wall materials. Generated maps are compared with their ASCII source, including cells, objective, doors, props and spawns. CQC route and open-door sight-line checks use real scene metrics; players run at 250 px/s in `player.tscn`. The `cqc` network fixture replays a test route through normal puppet input; it adds no gameplay AI. See `docs/testing/cqc-map.md` for measured timings, rendered loopback checks and the remaining human playtest.
- Still do a focused manual playtest for gameplay/feel changes: main menu -> host/join lobby -> start match -> verify replication, combat, and UI sync, with at least two clients (host + one client) on separate machines for networking changes.

## Commit & Pull Request Guidelines
- Recent commits are short, imperative summaries; optional prefixes like `fix:` are common. Keep subject lines specific.
- One logical change per commit (avoid mixing gameplay, UI, and asset churn).
- PRs should include: what changed, why, manual test steps/results, and screenshots/videos for visible UI/FX updates.
- Link related issue/task IDs when available.
